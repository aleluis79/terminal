# ssd-clarification

Revisa la especificación (spec) como un QA profesional. Analiza el documento y genera una lista numerada con las siguientes categorías:

1. Ambigüedades: afirmaciones vagas o sin criterios de aceptación claros.
2. Contradicciones: requisitos que chocan entre sí o con hechos establecidos.
3. Casos límite ausentes: escenarios edge cases, errores o condiciones no mencionados.
4. Conflictos con la constitución: violaciones o tensiones con `docs/constitution.md`.

## Reglas estrictas

- No propongas soluciones, correcciones ni implementaciones. Solo detecta y documenta los problemas.
- Formato: lista numerada por categoría, con cada punto siendo claro y verificable.
- Espera mi aprobación o instrucciones antes de continuar.
